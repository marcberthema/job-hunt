Search limitations — documented retrieval method still broken, refined workaround

  • The SKILL.md-documented URL pattern https://www.roberthalf.com/ca/en/jobs?jobType=CONTRACT&specialty=TECHNOLOGY&keywords=<term> still does not filter results as of this run — all six keyword fetches (direct HTTP and a live browser on the identical URL) returned the same unfiltered default listing (payroll, HR, and accounting roles). Confirmed again this run.
  • Refined workaround: submit each keyword through the on-page search box (redirects to https://www.roberthalf.com/ca/en/jobs/all/<keyword-slug>), then apply the page's own Job Type filter chip and select Contract / Temporary to Hire before reviewing results. This reliably scopes to contract-only postings client-side and avoids reviewing dozens of Permanent/Temporary fuzzy matches that the skill's contract-only mandate excludes anyway.
  • This is a skill-maintenance item: .agents/skills/check-roberthalf/SKILL.md's Access section should be updated to this UI-driven workaround; flagged here rather than edited directly since it wasn't asked for.
