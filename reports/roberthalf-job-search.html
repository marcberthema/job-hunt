Search limitations — the documented retrieval method is broken

  • The SKILL.md-documented URL pattern https://www.roberthalf.com/ca/en/jobs?jobType=CONTRACT&specialty=TECHNOLOGY&keywords=<term> no longer filters results — all six keyword fetches (DevOps Engineer, Platform Engineer, Site Reliability Engineer, Cloud Engineer, DevSecOps Engineer, Forward Deployed Engineer) returned the identical, unfiltered default listing (payroll, HR, and accounting roles), confirmed both via direct HTTP and in a live browser with the same URL.
  • Working workaround found this run: submitting a search through the on-page search box redirects to a path-based URL, https://www.roberthalf.com/ca/en/jobs/all/<keyword-slug> (spaces as hyphens), which does return keyword-matched results via direct HTTP. This URL does not carry the jobType=CONTRACT&specialty=TECHNOLOGY scoping — results included Permanent roles and non-Technology specialties, so each result was individually screened rather than trusting the URL to pre-filter.
  • This is a skill-maintenance item: .agents/skills/check-roberthalf/SKILL.md's Access section should be updated to the path-based pattern; flagged here rather than edited directly since it wasn't asked for.
